# Mocapi 0.14.0 → 1.0.0-SNAPSHOT (MCP `2026-07-28`)

**Date:** 2026-07-30
**Status:** Approved, ready for implementation planning

## Goal

Upgrade `mocapi-enterprise-demo` from Mocapi 0.14.0 to the locally built
1.0.0-SNAPSHOT, which implements MCP protocol revision `2026-07-28`
exclusively. Reach **functional parity** — the demo does everything it does
today, on the new protocol — and bring the documentation back in line with what
the code actually does.

Explicitly out of scope: adopting new 1.0 capabilities (`mocapi.oauth2.required-scopes`,
MRTR elicitation, typed progress emitters). Those are follow-on work once the
demo is compliant and upgraded.

## Why this is not a version bump

Mocapi 1.0 is a clean-break rewrite (ADR-0019). The parts that touch this demo:

- **Stateless core** (ADR-0020). The `initialize` handshake, sessions, and
  `Mcp-Session-Id` are gone. Every request carries `protocolVersion`,
  `clientInfo`, and `clientCapabilities` in its `_meta` envelope;
  `server/discover` advertises versions and capabilities.
- **POST-only Streamable HTTP.** `GET` and `DELETE` on `/mcp` return
  `405`. The standalone SSE stream and `Last-Event-ID` resumability are gone
  from the protocol. Per-request SSE (progress on a live call) remains.
- **Required routing headers** on every request: `MCP-Protocol-Version`,
  `Mcp-Method`, and — on `tools/call` / `prompts/get` — `Mcp-Name`.
  Mismatches return `-32020 HeaderMismatch`.
- **`mocapi.session-encryption-master-key` no longer exists.** There is no SSE
  resume token to encrypt.
- **MDC keys changed**: `mcp.session` is gone, `mcp.client.name` is new.

The Java blast radius is small: the demo touches only `@McpTool`,
`@RequiresScope`, `McpFilterChainCustomizer`, and
`McpMetadataFilterChainCustomizer`. The documentation blast radius is large.

## 1. Build and dependencies

Mocapi 1.0.0-SNAPSHOT is already installed in `~/.m2` (2026-07-30 09:10–09:11):
all thirteen modules this demo resolves, plus the BOM. **Do not build the mocapi
repo from this session** — another agent is actively working in
`~/IdeaProjects/mocapi`, and a concurrent `mvn install` risks disrupting it.

If a required artifact turns out to be missing or stale, stop and ask rather
than building. Note that the other agent may reinstall mid-flight, so an
unexpected compile error after a previously clean build may mean the dependency
moved underneath us, not that our migration is wrong.

In `pom.xml`:

- `mocapi.version` → `1.0.0-SNAPSHOT`.
- Remove the `substrate-postgresql` and `substrate-crypto` dependencies, the
  `substrate-bom` import, and the `substrate.version` property. Mocapi 1.0 has
  zero substrate references; substrate was in this demo solely to back Mocapi
  session state, which no longer exists. Nothing in the demo uses substrate
  directly.
- The Mocapi artifact set is otherwise unchanged: `mocapi-streamable-http-spring-boot-starter`,
  `mocapi-oauth2`, `mocapi-jakarta-validation`, `mocapi-logging`, `mocapi-otel`,
  `mocapi-actuator`, and `mocapi-spring-security-guards` all still exist in 1.0.

## 2. Java changes

**Delete `EncryptionBootstrap`**, its test `EncryptionBootstrapTest`, and
`src/main/resources/META-INF/spring.factories`. Both properties it generated are
gone: `mocapi.session-encryption-master-key` was removed by the protocol
rewrite, and `substrate.crypto.shared-key` leaves with substrate.
`mocapi.mrtr.secret` needs no equivalent bootstrap — Mocapi generates an
ephemeral key itself when the property is blank.

`MocapiDemoConfig` needs **no change**. Its two customizers only layer CORS onto
Mocapi's chains. The 1.0 restriction is that `McpFilterChainCustomizer` is no
longer the place for *authorization* rules; this demo never put any there.

The tool classes (`CatalogTools`, `FeedbackTools`, `ToolProposalTools`) are
expected to need no change — they use only `@McpTool` and `@RequiresScope`, with
no handler context, elicitation, or progress reporting. This is verified at
compile time rather than assumed.

## 3. Configuration (`application.properties`)

- `mocapi.demo.cors.allowed-methods`: `GET,POST,DELETE,OPTIONS` → `POST,OPTIONS`.
  `GET` and `DELETE` now return `405` by spec.
- `mocapi.demo.cors.exposed-headers`: drop `Mcp-Session-Id`; keep
  `WWW-Authenticate`.
- `mocapi.demo.cors.allowed-headers=*` already admits the new required routing
  headers, so the value is unchanged — but the surrounding comment should name
  `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name` so the wildcard is
  understood as deliberate.
- Remove `substrate.postgresql.notifier.poll-timeout` and the substrate half of
  the schema-ownership comment. Liquibase and the catalog schema are untouched —
  Postgres stays, it simply stops hosting `substrate_*` tables.

## 4. Documentation and bench

The README is wrong in six places once the upgrade lands. Each is a rewrite, not
a find-and-replace:

1. **Quickstart** (~lines 61–90). The `initialize` → capture `Mcp-Session-Id` →
   `notifications/initialized` sequence is replaced by direct POSTs carrying the
   routing headers, with `server/discover` as the capability probe.
2. **Positioning** (lines 19, 39). "Persistent encrypted sessions" is no longer
   a pillar. It is replaced by the stateless-request story: horizontal scale
   with no shared session state at all.
3. **Encryption keys** (lines 155–156, 353–354). `MOCAPI_SESSION_ENCRYPTION_MASTER_KEY`
   and `SUBSTRATE_CRYPTO_SHARED_KEY` are deleted from the prose and the env-var
   table.
4. **Transport section** (lines 228–232). POST-only; no standalone SSE stream,
   no `Last-Event-ID` resume, no session ids, no resume-token encryption.
   Per-request SSE for progress still exists and should be described as such.
5. **MDC table** (line 292 area). Drop `mcp.session`, add `mcp.client.name`.
6. **`substrate-postgresql` section** (lines 323–330) and the substrate entries
   in the DB-tables list (line 151). Deleted.

`bench/local-tool-call.js` performs an initialize handshake and must be rewritten
for the new wire shape, or the benchmark will not run. `bench/results/*` and the
two writeups are historical records of 0.x runs and stay untouched.
