# Mocapi 0.14.0 → 1.0.0 (MCP `2026-07-28`)

**Date:** 2026-07-30
**Status:** Dependency upgrade done and verified; cleanup and docs outstanding

## Goal

Upgrade `mocapi-enterprise-demo` from Mocapi 0.14.0 to Mocapi 1.0.0, which
implements MCP protocol revision `2026-07-28` exclusively. Reach **functional
parity** — the demo does everything it does today, on the new protocol — and
bring the documentation back in line with what the code actually does.

Explicitly out of scope: adopting new 1.0 capabilities (`mocapi.oauth2.required-scopes`,
MRTR elicitation, typed progress emitters). Those are follow-on work once the
demo is compliant and upgraded.

## Status

The dependency upgrade is **complete and verified against a running app**. What
remains is cleanup and documentation, not repair.

Done:

- `mocapi.version` → `1.0.0-SNAPSHOT` (interim; see §1).
- `opentelemetry-instrumentation.version` → `2.21.0-alpha`, fixing a
  pre-existing defect unrelated to this upgrade (§2).
- Verified: compiles, 46/46 tests, boots in ~4s, `GET /mcp` → 405,
  `server/discover` returns `supportedVersions: ["2026-07-28"]` with
  `_meta.serverInfo`, and `tools/list` / `tools/call` return correct data over
  OAuth2. Error paths return JSON-RPC in 4–8ms.

Outstanding: substrate removal (§3), `EncryptionBootstrap` deletion (§4),
configuration (§5), documentation and bench (§6).

## What running it changed about this plan

The original spec assumed the migration would be repair work. It is not — the
demo runs **unmodified** on 1.0.0 apart from the version bump. The Java surface
the demo touches (`@McpTool`, `@RequiresScope`, and the two filter-chain
customizers) is unchanged in 1.0, and dead configuration (`substrate.*`,
`mocapi.session-encryption-master-key`) is ignored rather than fatal.

Two consequences:

1. The remaining work is **cleanup and honesty in the docs**, and can be
   sequenced at leisure. Nothing is broken while it is pending.
2. `mvn clean verify` is **not sufficient evidence** of a successful migration.
   The suite passed 46/46 against an app whose error path returned HTTP 503 —
   every test is a unit test and none exercise an error path or the transport.
   See §7.

## Why this is not a version bump

Mocapi 1.0 is a clean-break rewrite (ADR-0019). The parts that touch this demo:

- **Stateless core** (ADR-0020). The `initialize` handshake, sessions, and
  `Mcp-Session-Id` are gone. Every request carries `protocolVersion`,
  `clientInfo`, and `clientCapabilities` in its `_meta` envelope;
  `server/discover` advertises versions and capabilities.
- **POST-only Streamable HTTP.** `GET` and `DELETE` on `/mcp` return
  `405`. The standalone SSE stream and `Last-Event-ID` resumability are gone
  from the protocol. Per-request SSE (progress on a live call) remains.
- **Required routing headers** on every request: `MCP-Protocol-Version`,
  `Mcp-Method`, and — on `tools/call` / `prompts/get` — `Mcp-Name`.
  Mismatches return `-32020 HeaderMismatch`.
- **`mocapi.session-encryption-master-key` no longer exists.** There is no SSE
  resume token to encrypt.
- **MDC keys changed**: `mcp.session` is gone, `mcp.client.name` is new.

The Java blast radius is small: the demo touches only `@McpTool`,
`@RequiresScope`, `McpFilterChainCustomizer`, and
`McpMetadataFilterChainCustomizer`. The documentation blast radius is large.

## 2. OpenTelemetry alignment (done)

**This was a pre-existing defect, not caused by the upgrade** — resolving with
`-Dmocapi.version=0.14.0` produced the identical broken resolution. It is
recorded here because it was found during this work and because it silently
broke every error path in the demo.

`opentelemetry-instrumentation.version` was `2.26.1-alpha`. That release's
logback appender calls the **stable** `LogRecordBuilder.setException(Throwable)`,
unguarded — a method that graduated from the incubator API in otel-java 1.60.1.
Spring Boot 4.0.5 manages `opentelemetry-bom` at 1.55.0 and its BOM is imported
first, so Boot wins the ordering and the appender runs against an API that lacks
the method. Result: `NoSuchMethodError` on the first logged exception, thrown
from inside the logging call in mocapi's exception translator. The escaping
`Error` stranded the request until Tomcat's 30s async timeout, and the client
received an HTML `503` instead of a JSON-RPC error.

Fixed by pinning `2.21.0-alpha`, which routes through the guarded
`ExtendedLogRecordBuilder` incubator interface present in 1.55.0. The pom
carries a comment recording the constraint: this version must move only
alongside Boot's managed `opentelemetry.version`.

Note the appender is genuinely unmanaged — neither Boot nor `mocapi-bom`
versions `opentelemetry-logback-appender-1.0`, so the demo must pin it. There is
no "take the managed version" option to fall back to.

## 3. Substrate removal

Remove the `substrate-postgresql` and `substrate-crypto` dependencies, the
`substrate-bom` import, and the `substrate.version` property. Mocapi 1.0 has
zero substrate references; substrate was in this demo solely to back Mocapi
session state, which no longer exists. Nothing in the demo uses substrate
directly.

Postgres itself stays — it hosts the catalog schema. It simply stops hosting the
`substrate_*` tables.

## 4. Java changes

**Delete `EncryptionBootstrap`**, its test `EncryptionBootstrapTest`, and
`src/main/resources/META-INF/spring.factories`. Both properties it generated are
gone: `mocapi.session-encryption-master-key` was removed by the protocol
rewrite, and `substrate.crypto.shared-key` leaves with substrate.
`mocapi.mrtr.secret` needs no equivalent bootstrap — Mocapi generates an
ephemeral key itself when the property is blank.

`MocapiDemoConfig` needs **no change**. Its two customizers only layer CORS onto
Mocapi's chains. The 1.0 restriction is that `McpFilterChainCustomizer` is no
longer the place for *authorization* rules; this demo never put any there.

The tool classes (`CatalogTools`, `FeedbackTools`, `ToolProposalTools`) are
expected to need no change — they use only `@McpTool` and `@RequiresScope`, with
no handler context, elicitation, or progress reporting. This is verified at
compile time rather than assumed.

## 5. Configuration (`application.properties`)

- `mocapi.demo.cors.allowed-methods`: `GET,POST,DELETE,OPTIONS` → `POST,OPTIONS`.
  `GET` and `DELETE` now return `405` by spec.
- `mocapi.demo.cors.exposed-headers`: drop `Mcp-Session-Id`; keep
  `WWW-Authenticate`.
- `mocapi.demo.cors.allowed-headers=*` already admits the new required routing
  headers, so the value is unchanged — but the surrounding comment should name
  `MCP-Protocol-Version`, `Mcp-Method`, and `Mcp-Name` so the wildcard is
  understood as deliberate.
- Remove `substrate.postgresql.notifier.poll-timeout` and the substrate half of
  the schema-ownership comment. Liquibase and the catalog schema are untouched —
  Postgres stays, it simply stops hosting `substrate_*` tables.

## 6. Documentation and bench

The README is wrong in seven places once the upgrade lands. Each is a rewrite,
not a find-and-replace:

1. **Quickstart** (~lines 61–90). The `initialize` → capture `Mcp-Session-Id` →
   `notifications/initialized` sequence is replaced by direct POSTs carrying the
   routing headers, with `server/discover` as the capability probe.
2. **Positioning** (lines 19, 39). "Persistent encrypted sessions" is no longer
   a pillar. It is replaced by the stateless-request story: horizontal scale
   with no shared session state at all.
3. **Encryption keys** (lines 155–156, 353–354). `MOCAPI_SESSION_ENCRYPTION_MASTER_KEY`
   and `SUBSTRATE_CRYPTO_SHARED_KEY` are deleted from the prose and the env-var
   table.
4. **Transport section** (lines 228–232). POST-only; no standalone SSE stream,
   no `Last-Event-ID` resume, no session ids, no resume-token encryption.
   Per-request SSE for progress still exists and should be described as such.
5. **MDC table** (line 292 area). Drop `mcp.session`, add `mcp.client.name`.
6. **`substrate-postgresql` section** (lines 323–330) and the substrate entries
   in the DB-tables list (line 151). Deleted.
7. **Keycloak credentials.** The quickstart names `client_id=mcp-demo-client` /
   `client_secret=mcp-demo-secret`, which do not exist in
   `keycloak/mocapi-demo-realm.json`. The realm ships `meridian-viewer`,
   `meridian-oncall`, and `meridian-owner` (secret = `<client-id>-secret`, all
   service-account clients). This is a pre-existing doc bug, independent of the
   upgrade, and it means the documented quickstart cannot currently obtain a
   token.

`bench/local-tool-call.js` performs an initialize handshake and must be rewritten
for the new wire shape, or the benchmark will not run. `bench/results/*` and the
two writeups are historical records of 0.x runs and stay untouched.

## 7. Verification

`mvn clean verify` is necessary but **not sufficient** — the suite is entirely
unit tests, and it passed 46/46 against an app whose every error path returned
HTTP 503. Verification must exercise the running server.

1. `mvn clean verify` green.
2. `docker compose up -d`, then execute the rewritten README quickstart against
   the running app — obtain a token with a real realm client, call
   `server/discover`, and make one authenticated `tools/call` with the new
   routing headers. The quickstart must be run, not merely written.
3. Confirm `GET /mcp` returns `405` (evidence the transport is the 1.0 one).
4. **Exercise an error path.** Call a tool with an argument that makes it throw
   (e.g. `service-lookup` with a name not in the catalog) and confirm a
   JSON-RPC `isError` result returns promptly. A 30s delay or an HTML error body
   means the OpenTelemetry alignment of §2 has regressed.
5. Confirm the app starts with no substrate on the classpath and no
   `substrate_*` tables created.
6. Confirm no `Mcp-Session-Id` appears anywhere in the response headers.

## Upstream fix this work produced

The stranded-request behavior described in §2 was reported to mocapi and fixed
before 1.0.0: `StreamableHttpController#handleCall` caught `Exception`, so an
`Error` escaping the handler skipped `transport.abort(...)` — the only thing that
completes the response future — and the request hung until the container's async
timeout. It now aborts the request and rethrows, so the connection fails fast
while the `Error` still propagates. Mocapi's OpenTelemetry guide also gained a
version-alignment warning in place of a bare version number.

Relevant to this demo only as reassurance: with mocapi 1.0.0, a future classpath
mismatch produces a prompt JSON-RPC error rather than a 30-second hang.
